# bun.ink — Roadmap & Feedback

This is the public roadmap and feedback tracker for **[bun.ink](https://bun.ink/?utm_source=github&utm_medium=roadmap&utm_campaign=roadmap_repo)** — a browser-based writing app that stores your texts as Markdown in your own GitHub repository. Branches, commits and pull requests, without the terminal. Your drafts live in a repo: versioned, reviewable, and ready for AI agents to work on.

This repository contains no application code. It exists so you can see what we are working on and tell us what you need.

## What's here

- **[ROADMAP.md](ROADMAP.md)** — what we are building now, next, and later
- **[Issues](../../issues)** — one per roadmap item, plus every feature request and bug report
- **[Discussions](../../discussions)** — questions, workflows, and anything that isn't a concrete request

## How to influence the roadmap

1. **Search the [issues](../../issues) first** — someone may have asked already.
2. **React with 👍** on the issues you care about. We sort by reactions when deciding what to build next, so a thumbs-up is a real vote.
3. **Open a [feature request](../../issues/new?template=feature_request.yml)** if nothing matches, or a [bug report](../../issues/new?template=bug_report.yml) if something is broken.

Every issue carries a `status:` label — `planned`, `in-progress`, `shipped` or `not-planned` — so you can always see what became of your suggestion. We also mark an `area:` so related requests are easy to find.

## What we won't do here

We don't put dates on roadmap items. Estimates from a small team turn into broken promises, and a roadmap nobody trusts is worse than no roadmap. Order signals intent, not a schedule.

## Security

Please do **not** report security issues in public. Write to [info@bun.ink](mailto:info@bun.ink) instead.
